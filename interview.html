Reflection: Mock Interview Video

As part of preparing for the internship application process, we were required to record a mock interview video presenting ourselves and our motivations for entering the field.

I needed to present myself confidently on camera and clearly articulate my background and what drew me to Application Development.

The biggest challenge was getting comfortable in front of the camera, as self-presentation is something I have always had to consciously work on. I pushed through that discomfort and focused on the content itself, which required me to think deeply about my personal journey and the specific experiences that led me to choose this career path.

Recording the video ended up being more valuable than I expected. Working through the nervousness and having to put my motivations into words gave me more clarity on where I want to go in my career. It also gave me something concrete to reflect on and improve for real interviews going forward.

Reflection: CV Coded Using Markdown

As part of the internship module, I was required to create a CV coded in Markdown and publish it to my GitHub profile. I had not worked with Markdown in a meaningful way before this task.

I needed to learn Markdown syntax and use it to produce a clean, well-structured CV.

I started by researching Markdown syntax and familiarising myself with the basics such as headings, bullet points, links and formatting. I then applied what I learned to build out the structure and content of my CV.

I completed the CV and came away with a working understanding of Markdown. It also made me realise how practical Markdown is beyond just this task, particularly for writing README files and documentation, which is something I have already started applying to my GitHub projects.

Reflection: Published on GitHub Pages

The assignment required us to publish our work publicly using GitHub Pages, which was a tool I had not used before.

I needed to deploy my GitHub profile and CV to a live GitHub Pages link.

The initial setup was confusing as I was not familiar with how GitHub Pages works. I worked through it without a step-by-step guide at first, ran into a few issues, and eventually got it live. I then went back and redid the process once I understood it better, which helped solidify how it actually works.

Going through it twice made a noticeable difference. The second time around it was straightforward and I understood what each step was doing. I now have a working published link and a clear understanding of how static site hosting through GitHub Pages works, which is a useful skill for showcasing projects in future.
